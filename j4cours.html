🧱 4) Types pour Page Objects (architecture propre)

Objets: Ça prépare directement à Playwright📌(car Playwright utilise énormément de types complexes). 


					interface BasePage {
					  url: string;
					  goto(): Promise<void>;
					}
					// goto(): Promise<void>; => goto() ne renvoie pas un résultat immédiat
					// goto() renvoie une Promise
					// Cette Promise se résoudra plus tard quand l’action sera terminée
					// Une Promise = un objet qui représente une opération ASYNCHRONE(C’est un truc qui n’est pas fini tout de suite).
			    

					class LoginPage implements BasePage {
					  constructor(private page: Page) {}

					  url = "https://site.com/login";

					  async goto() {  await this.page.goto(this.url); }
						
					  get email() { return this.page.locator("#email"); }   
					  get password() { return this.page.locator("#password"); }
					  get submit() { return this.page.locator("#submit"); }
					   
					}
					1. On implemente le 1er paramètre(url)
					2. le 2ème paramètre( goto)
					3. les actions( il y en 3)

					// locator() → le sélecteur CSS (ou XPath) qui permet à Playwright de trouver l'elt dans la page
🧱 5) Fixtures avancées (Playwright Pro)

Objets: Injection d'une fixture dans un test. 


					import { test as base } from "@playwright/test";
					interface MyFixtures {
					  loginPage: LoginPage;
					}
					const test = base.extend<MyFixtures>({
					  loginPage: async ({ page }, use) => { await use(new LoginPage(page)); }
					});
					export { test };
			    

					test("login works", async ({ loginPage }) => {
					  await loginPage.goto();
					  await loginPage.email.fill("andjib@test.com");
					  await loginPage.password.fill("123456");
					  await loginPage.submit.click();
					});

					//Dans Playwright, test est une fonction importée(pas un objet) :
					import { test, expect } from "@playwright/test";
					//Et sa signature est :
					test(name: string, fn: TestFunction)
					name → le nom du test
					fn → fonction qui reçoit les fixtures typées
			    

					// 👉 base → test original. le test “brut”, non modifié.
					// 👉 test → Ton test. Amélioré avec tes fixtures. Construit à partir de base
					// 👉 @playwright/test → un package npm appartenant au “scope” playwright

					// 👉 { page } = les fixtures Playwright déjà existantes. Playwright fournit automatiquement : Page, context, browser, request, etc
					// 👉 use = Fonction qui enregistre ta fixture dans le test. 
					//      Tu dois appeler use() pour dire à Playwright : “Voici la valeur de ma fixture, injecte-la dans le test.”
					// 👉 new LoginPage(page) crée la fixture(construit l’objet que tu veux injecter dans tes tests.)
					// 👉 export { test } =  Ça rend la variable test disponible pour les autres fichiers.

					// 👉 fill() =  remplit un champ de formulaire avec un texte.
			    

					 1. Page Object → définit les actions
					 2. Fixture → construit le Page Object
					 3. Test → utilise la fixture

5. Fixtures avancées (Playwright Pro)

🟦 C’est quoi un “scope” dans npm ?
Un espace de nom (namespace) pour regrouper des packages. Exemples:
  • ✔ @angular/core, @nestjs/common
  • ✔ @types/node
  • ✔ @playwright/test
Le scope:
  • ✔ Commence par @
  • ✔ Indique une “famille” de packages
  • ✔ Permet d’organiser le code proprement
🟦 Que fait page.fill() ?
Remplit un champ de formulaire avec un texte.
C’est l’équivalent de :
  • ✔ cliquer dans un input
  • ✔ effacer ce qu’il y a dedans
  • ✔ taper du texte
Playwright fait tout ça automatiquement.
SYNTAXE:
await page.fill(selector, value);
  • selector → Adresse input (CSS,locator)
  • value → Texte du champ
EXEMPLE:
await page.fill("#email", "tamim@test.com");
