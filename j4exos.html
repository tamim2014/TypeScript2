🧱 Exo1/Q1: Interface de modélisation

Objets: Définir la structure de ta page Login(input,button,message). 


					Définis une interface LoginPageModel, modèle typé de ta page . 
			    

					interface LoginPageModel {
					    inputs: {
					        email: string;
					        password: string;
					    };
					    buttons: {
						    submit: string;
					    };
					    messages: {
						    error: string;
					    };
					}
					➡️ Tu viens de faire un modèle typé de ta page: C’est ton “plan architectural”.
🧱 Exeo1/Q2: Page Object typé

Objets: Implémente une classe qui utilise le modèle LoginPageModel 


					Dans une classe LoginPageModel, instancier un objet model, qui va faire les actions suivantes(sur la page https://site.com/login ):   
					1. Saisir l'email 
					2. Le password
					3. Valider 
					4. Gerer les message d'erreurs 
			    

					import { Page } from "@playwright/test";
					class LoginPage {
					   constructor(private page: Page) {}
					   model: LoginPageModel = {
					       inputs: { email: "#email", password: "#password" },
					       buttons:{ submit: "#submit" },
					       messages: { error: ".error" }
					   };
					   async goto() { await this.page.goto("https://site.com/login"); }
					   
					   get email()  { return this.page.locator(this.model.inputs.email); }
					   get password() { return this.page.locator(this.model.inputs.password); }
					   get submit() { return this.page.locator(this.model.buttons.submit); }
					   get errorMessage() { return this.page.locator(this.model.messages.error); }
					}
					➡️ Tu as un Page Object propre, typé, structuré.
					➡️ Tu utilises ton modèle pour éviter les strings partout.
🧱 Exo1/Q3: Fixture avancée (🌱 Bloc pattern)

Objets: Une fixture qui injecte le Page Object ( loginPage de type LoginPage) 


					3.1 Etendre le test Playwright pour injecter ton Page Object.  
					3.2 Définir l'interface: Elle porte le nom de la fixture
					3.3 Instancier l'interface: const test = base.extend<nomFixture>(...);  
					3.4 Mettre le test à disposition   
			    

					import { test as base } from "@playwright/test"; // @playwright/test = un package npm appartenant au “scope” playwright.
					interface MyFixtures {
					  loginPage: LoginPage;
					}
					const test = base.extend<MyFixtures>({  loginPage: async( { page }, use )   =>   {const lp = new LoginPage(page); await use(lp); }      });
					export { test };
🧱 Exo1/Q4: Dataset( Jeu de données typées)

Objets: Une liste d'utilisateurs contenant leurs email,password, et rôles 


					4.1 Définir une interface avec les paramètres de chaque utilisateur
					   • On doit connaître l'adresse mail, le mot de passe, et le rôle de chaque utilisateur
					   • Un utilisateur peut être admin, utilisateur ordinaire, ou invité
					4.2 Définir un dictionnaire typé(relatif à cet interface) pour mettre la liste des utilisateurs
			    

				interface TestUser {
				  email: string;
				  password: string;
				  role: "admin" | "user" | "guest";
				}

				const users: Record<string, TestUser> = {
				  admin: {
					email: "admin@test.com",
					password: "123456",
					role: "admin"
				  },
				  user: {
					email: "user@test.com",
					password: "123456",
					role: "user"
				  }
				};
				➡️ users = ton jeu de données (dataset). Dictionnaire des utilisateurs(typé   TestUser)
				➡️ Rien à voir avec Playwright : c’est toi qui le définis.
🧱 Exo1/Q5: Test complet

Objets: Utiliser tout ce qu'on a construit ci-haut pour construire un test 


					Tu utilises :
						✔️ ton Page Object: LoginPage(Bloc3)
						✔️ ta fixture: loginPage(Bloc3)
						✔️ ton dataset: users(Bloc4)
						✔️ ton modèle typé: TestUser(Bloc4)
					C’est l'architecture utilisée en entreprise.
			    

					import { test, expect } from "./fixtures";
					import { users } from "./data/users";

					test("admin can login", async ({ loginPage }) => {
					  const admin = users.admin;

					  await loginPage.goto();
					  await loginPage.email.fill(admin.email);
					  await loginPage.password.fill(admin.password);
					  await loginPage.submit.click();

					  await expect(loginPage.errorMessage).toBeHidden();
					});

Objectif: Un test complet utilisant une interface, un objet page, et une fixture

1. Interface de modélisation:

C'est le modèle typé d'une page.
👉 On y met les paramètre à tester
   - champs input,
   - button,
   - message
...etc)

2. Page Object typé

On implémente une classe qui utilise ce modèle. Dans cette classe:
  • ✔ On défini un objet d'instance du model
  • ✔ On annonce les action avec async
  • ✔ Et on lance les action avec l'objet d'instance

3. Fixture qui injecte ce Page Object

La fixture se construit en 4 étapes
  • 3.1 Etendre le test:
    Pour injecter ton Page Object
  • 3.2 Définir l'interface:
    Elle porte le nom de la fixture
  • 3.3 Instancier l'interface:
    const test = base.extend<nomFixture>(...);
  • 3.4 export { test };

➡️ L'action définie dans l'interface(ici loginPage) devient disponible dans tous tes tests
➡️ Plus besoin de créer la page à la main.
