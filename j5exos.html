🧱 Exo1/Q1: Type avancé

Objets: Définir un type générique Box<T> 


					//Exemple :
					interface User {
					  email: string;
					  password: string;
					  age: number;
					}
					//Ton type doit produire :
					{
					  email: string;
					  password: string;
					}
			    

					type OnlyStringProps<T> = {
					  [K in keyof T as T[K] extends string ? K : never]: T[K];

					  // Cf. Jour5/1.3 — Types conditionnels avancés.
					  // [K in keyof T as T[K] ]= [K in keyof T]: T[K]   est-ce la mm chose?

					};
			    

					✔️ Explication factory style
						  - On parcourt toutes les clés K de T
						  - On garde uniquement celles dont le type est string
						  - Les autres deviennent never → donc supprimées
						  
					✔️ Exemple
					interface User {
					  email: string;
					  password: string;
					  age: number;
					}

					type OnlyStrings = OnlyStringProps<User>;

					Résultat :
					{
					  email: string;
					  password: string;
					}
🧱 Exeo1/Q2: Logique métier typée

Objets: Dataset 


					type Role = "admin" | "user" | "guest";

					type Permissions = {
					  dashboard: boolean;
					  settings: boolean;
					  billing: boolean;
					};

					CONSTRUIRE UN "dataset typé" :
					const permissions: Record<Role, Permissions> = {
					  // admin: ...
					  // user: ...
					  // guest: ...
					};
					Tu remplis les permissions selon TA logique métier.
			    

					// Datasset 

					const permissions: Record<Role, Permissions> = {
					  admin: { dashboard: true, settings: true, billing: true },
					  user: { dashboard: true, settings: false, billing: false },
					  guest: { dashboard: false, settings: false, billing: false }
					};
			    

					🔹 Admin → accès total
					🔹 User → accès limité
					🔹 Guest → accès minimal

					Tu px mettre le type dans une variable RolePermissions: 
					  type RolePermissions = Record<Role, Permissions>;   =>   const permissions: RolePermissions 

					Tu peux changer la logique, mais celle-ci est cohérente.

🧱 Exo1/Q4: Test paramétré Playwright

Objets: Tester la permission d'accès au dashboard 


					👉 Écris un test qui :

					   1.boucle sur users // for (const u of users)

					   2.tente de se connecter

					   3.vérifie l’accès au dashboard selon permissions[u.role].dashboard

					Structure :
					for (const u of users) {
					  test(`login test for ${u.role}`, async ({ page }) => {
						// 1. login
						// 2. vérifier accès selon permissions[u.role].dashboard
					  });
					}
					Tu écris la logique toi-même.
			    

					import { test, expect } from "@playwright/test";

					for (const u of users) {
					  test(`login test for ${u.role}`, async ({ page }) => {
						// 1. Se connecter: Aller à la page de login
						await page.goto("https://site.com/login");

						// 2. Remplir les champs 👉  Cf  Jour5/Cours/4.1
						await page.fill("#email", u.email); // await loginPage.email.fill(u.email);
						await page.fill("#password", u.password); // await loginPage.password.fill(u.password);
						await page.click("#submit"); // await loginPage.submit.click();


						// 3. Vérifier l'accès selon les permissions
						const canAccessDashboard = permissions[u.role].dashboard;

						if (canAccessDashboard) {
						  await expect(page).toHaveURL(/dashboard/);
						} else {
						  await expect(page).not.toHaveURL(/dashboard/);
						}
					  });
					}
			    

					✔️ Explication
						 - Le test tourne 3 fois (admin, user, guest)

						 - La logique métier est centralisée dans permissions

						 - Le test ne contient aucune duplication

						 - Architecture propre, scalable, professionnelle

Objectif: Inventer des types (puissants, réutilisables, propres)

1. Les types utilitaires:

  • ✔ Partial<T>
  • ✔ Required<T>
  • ✔ Readonly<T>
  • ✔ Pick<T>
  • ✔ Omit<<T>
  • ✔ Record<T>
  • ✔ ReturnType<T>

permettent de tranceformer des types existants.
👉 Ce sont les “super‑pouvoirs” de TypeScript.

2. Les génériques

function identity<T>(value: T): T { ... }
  • ✔ ça permet d'inventer des types flexibles
  • ✔ ça évite les répétitions
  • ✔ ça améliore la sécurité du code

C'est pour de tranceformer des types existants.
👉C’est le cœur du TypeScript moderne.

3. Generic Interfaces & Types

On parle d'Interfaces génériques avancées et de types paramétrés

Comment écrire :

  • interface ApiResponse<T> {
  •  data: T;
  •  status: number;
  • }

Et comment les utiliser avec :
 → Des types complexes, des objets,
 → des tableaux, des fonctions
👉 C’est ce qui permet de modéliser des réponses API, des actions Playwright📌, etc.

4. Fonctions typées avancées

Il y en a 3 fonctions typées:
  • ✔ Les fonctions génériques,
  • ✔ les fonctions qui retournent des types complexes
  • ✔ les fonctions qui manipulent des objets typés
  • ✔ et les signatures de fonction

👉 Ça te prépare directement à Playwright,
car Playwright utilise énormément de types complexes.

5. Les types conditionnels

C’est le niveau “maestro”:
  • T extends U ? X : Y

👉C’est ce qui permet à TypeScript d’être intelligent.
